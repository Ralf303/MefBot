# Админка Pablo

Отдельное приложение Express: `npm run admin`. Оно не запускает бота, его cron и Telegram polling. Слушает только `127.0.0.1:3091`. Nginx направляет исключительно `/admin/` в этот процесс, существующие `/` и API на 8080 сохраняются.

Настройки входа находятся в игнорируемом `.env.admin`, образец — `.env.admin.example`. Данные MySQL и Redis берутся из `.env.prod`. Пользовательские ID и Telegram ID не редактируются, чтобы не нарушить связи. Пароли игровых ролей не возвращаются в браузер.

## Возможности

- Статистика пользователей, регистраций, балансов, вещей, кейсов, чатов, семей и записанных платежей. Данные кешируются на 30 секунд. «Профили обновлены» считает `updatedAt`, а не уникальных активных игроков.
- Поиск и страницы пользователей; редактирование всех игровых числовых параметров, имени и username.
- Просмотр, выдача, изменение, передача и удаление вещей. Проверка вместимости, пересчёт занятых слотов, снятие конфликтующей одежды и сброс кеша изображений.
- Каталог вещей с изображениями и отдельными профилями экземпляров.
- Кейсы, дома, видеокарты, стойки, игровые роли, таймеры бонусов, активность и ранг в семье. Удаление карты освобождает её стойку.
- Чаты: VIP, срок VIP, кейсы, игры, банк, имя и ссылка.
- Семейные балансы и улучшения; журнал игровых операций и отдельная история правок администратора.

Сохранение меняет только поля, отредактированные в форме. В транзакции блокируется актуальная запись и проверяется каждое исходное значение: при конкурентном изменении сервер возвращает 409 вместо перезаписи. Запись истории создаётся в той же транзакции.

Сессия действует 12 часов, хранится на сервере и сбрасывается при перезапуске админки. Cookie — Secure, HttpOnly, SameSite=Strict с областью `/admin`. Изменения требуют CSRF-токена. Вход ограничен по числу попыток. Изображения доступны только после входа и только из каталога `img`.

Для первого запуска создаются собственные таблицы `adminAudits`, `gameLogs`, `gameLogUsers`; существующие таблицы приложение не мигрирует. Изменения каталога типов вещей через UI не предусмотрены, редактируются отдельные экземпляры. Удаление пользователей и чатов отключено.

Историческая колонка `roles.roleId` автоматически отображается как ID владельца внутри процесса админки. Схема БД и авторизация существующего API при этом не меняются.

## Игровой журнал

Новые события записываются в `gameLogs`, участники с ID в БД и Telegram ID — в `gameLogUsers`. Старая таблица `logs` сохранена без изменений и доступна через переключатель «Старый архив». Старые userOne/userTwo содержали балансы, поэтому восстановить из них надёжные ID участников нельзя.

Контекст Telegram update охватывает обработчики и сцены. Hooks фиксируют создание, изменение и удаление игровых записей: пользователей, ресурсов, вещей, кейсов, домов, видеокарт, стоек, семей, рангов, улучшений, чатов, платежей и раздач. Массовые обновления, удаления и increment репутации также учитываются. Для операций без записи в БД отдельно добавлены события приглашений в семью и публикации раздач. Совместимые старые функции логирования добавляют детали в новый журнал вместо повторного сохранения старых строк.

Изменения транзакции добавляются после commit внешней транзакции, а не savepoint. При rollback они отбрасываются. Журнал сохраняется отдельной транзакцией; сбой записи журнала сообщается в PM2 stderr, но не откатывает выполненную игровую операцию. Обычные команды, ничего не изменившие, не создают записей. Пароли ролей, JWT, платёжные payload/chargeId и текст обычной переписки не сохраняются. Синхронизация имени/username из Telegram и счётчики сообщений не создают событий.

Из фоновых задач журналируются награды активности, месячной битвы семей, ежедневные ключи, изъятие дома и истечение VIP. Частое начисление гемов, майнинг, расход охлаждения, изменение изображений, таймеры и технические миграции не журналируются. Команды сторонней модерации имеют статус «Команда замечена»: бот сам не применяет мут/бан.

В UI доступны пользователь (Telegram ID / ID БД / username), любой участник или инициатор, тип события, ресурс, даты в московском времени, чат, источник, статус, объект и его ID, ID записи, поиск в деталях. Снимки участников позволяют находить старый username после переименования. Для массовых операций детали ограничены 100 изменениями; число пропущенных изменений показывается явно. Фильтр пользователя может дополнительно включать операции для всех пользователей. В профиле пользователя есть ссылка на его журнал.

Новые записи индексируются по времени, типу, источнику, чату, статусу и участникам. Поиск деталей и JSON-фильтры применяются к выбранным записям; для больших журналов сначала задавайте период или тип события. Автоматическое удаление истории не включено.
